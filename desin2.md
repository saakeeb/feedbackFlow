FeedbackFlow — Design System & Product Experience

Say what needs to be said.

Give constructive feedback on any paragraph, idea, decision, document, or conversation — without exposing your identity.

1. Design Vision

FeedbackFlow is a communication product built around a simple human problem:

People often know what should be improved, but they are afraid to say it because their identity is attached to the feedback.

FeedbackFlow removes that fear.

The product should make it easy for someone to:

Read something.
Notice something that could be better.
Select the relevant paragraph or content.
Leave constructive feedback.
Remain anonymous.
Start a meaningful conversation without worrying about personal exposure.

The visual design should communicate:

Confidence
Privacy
Intelligence
Calmness
Editorial quality
Trust
Serious communication

It should not feel like:

A generic HR dashboard
A corporate enterprise portal
A social-media feed
A colorful SaaS template
An AI-generated dashboard
A notification-heavy productivity app

Large whitespace
High-contrast sections
Oversized headlines
Image-led storytelling
Minimal UI chrome
Controlled typography

Do not copy the car-rental subject matter.

FeedbackFlow should translate the visual language into:

Luxury editorial communication software.

The result should feel closer to a premium publication or high-end digital product than a conventional workplace SaaS application.

5. Core Design Principle
Fearless Feedback

Every major design decision should support one question:

Does this make it easier for someone to give honest, constructive feedback?

If a design element increases hesitation, remove it.

If an interaction makes anonymity unclear, redesign it.

If the interface distracts from the content, simplify it.

6. Brand Message

The primary product message should focus on anonymous constructive feedback, not generic collaboration.

Preferred messaging:

Supporting message:

Alternative:

Good ideas deserve honest feedback.

Supporting message:

Comment directly on what matters, stay anonymous, and help make the work better.

Another:

Don't hold back the feedback that could make things better.

13. Typography

Typography is one of the most important parts of the design.

The product should use a strong display typeface paired with a highly readable UI/body typeface.

Recommended direction:

Display

Use a distinctive editorial grotesk or modern display sans.

Examples:

Space Grotesk
Manrope
DM Sans
Satoshi
General Sans
Neue Montreal

A serif can optionally be introduced for editorial moments.

Body

Use a highly readable neutral sans.

Examples:

Inter
DM Sans
IBM Plex Sans
Geist

Do not automatically use Inter everywhere.

The display face should give FeedbackFlow its personality.

14. Typography Scale

Large marketing headings should be genuinely large.

Example:

--text-display: clamp(4rem, 9vw, 9rem);
--text-h1: clamp(3rem, 6vw, 6rem);
--text-h2: clamp(2.5rem, 4vw, 4.5rem);
--text-h3: clamp(1.75rem, 3vw, 3rem);

Body:

--text-body-lg: 1.25rem;

--text-small: 0.875rem;

Do not use large typography everywhere.

Large type should indicate:

20. Anonymous Status

Anonymity should never be hidden behind fine print.

Before submission:

● Anonymous
Your identity will not be displayed with this feedback.

The user should understand the privacy model before pressing Submit.

Avoid vague language such as:

“Don't worry, you're safe.”

Privacy messaging must describe the actual technical behavior.

21. Fearless Feedback UX

The interface should actively reduce psychological friction.

Instead of:

“Enter your feedback”

use:

What would make this better?

Instead of:

“Comment”

consider:

Suggest an improvement

Instead of:

“Submit”

consider:

Send anonymously

These phrases encourage constructive feedback rather than criticism for its own sake.

22. Constructive Feedback

FeedbackFlow should encourage useful feedback.

The feedback composer can subtly guide users:

What would make this better?

Try:
• Explain what isn't working
• Suggest an alternative
• Give an example
• Focus on the work, not the person

This should be guidance, not an annoying form checklist.

31. Meetings

Meetings are secondary to the core anonymous-feedback experience.

Do not let the meeting feature visually dominate the product.

The positioning should be:

Feedback shouldn't disappear when the meeting ends.

Meeting notes can become another place where people leave constructive anonymous comments.

42. Empty States

Empty states should be human.

Instead of:

Keep loading states quiet.

45. Privacy UX

Privacy should be visible throughout the feedback flow.

Relevant moments:

Before writing
Before submitting
After submitting
Inside feedback thread
Inside account settings

The product should never make the user wonder:

“Can my manager see that I wrote this?”

The interface should answer that question clearly.

46. Trust Language

Use precise language.

Good:

Your name isn't displayed with anonymous feedback.

Only use stronger claims if technically guaranteed.

Avoid vague marketing:

“Your feedback is 100% completely secure forever.”

Trust comes from clarity.

57. What Makes FeedbackFlow Different

The strongest visual/product idea is not:

“FeedbackFlow has feedback, meetings, resources and analytics.”

The strongest idea is:

Feedback can be attached directly to the thing being discussed — while the person giving it remains anonymous.

That should be visually obvious.

The paragraph is the center.

The feedback is attached to it.

The identity is secondary.

The conversation is the outcome.

66. Final Design Principle

FeedbackFlow should feel like a place where people can finally say:

“I noticed something.
I think it could be better.
Here's why.
And I'm not afraid to tell you.”

The interface should make that moment feel natural.

Not corporate.

Not intimidating.

Not anonymous for the sake of anonymity.

Anonymous so people can be honest.

And honest so the work can become better.
